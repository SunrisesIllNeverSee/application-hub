### Deviations from a real fresh machine (all test-environment, all labelled)

1. **Claude Code's own login.** The `claude` process keeps the real `HOME`, because its OAuth login lives in the macOS login Keychain and an empty `HOME` cannot reach it. Linking the Keychain into the scratch home was denied by the permission system, so it was not done. Isolation therefore comes from `--restricted`, `--strict-mcp-config`, an empty cwd outside any repo, and a clean environment (no `AQUA_*`, no parent-session markers). The companion, npm and every user file use the scratch `HOME`.
2. **TLS and WebFetch.** WebFetch upgrades `http` to `https` and refuses dot-less hosts such as `localhost`. The harness therefore serves `https://127.0.0.1:<port>` with a throwaway local CA, which the `claude` process trusts (`NODE_EXTRA_CA_CERTS`) along with npm and curl in the user shell. It also passes `skipWebFetchPreflight`. The phase-1 prompt says: "For this session AQUA's site is https://127.0.0.1:18443, a pre-release copy of https://aquaidp.xyz. Wherever its pages say https://aquaidp.xyz, use that instead." Shell blocks get the same origin mapping. The agent made 0 WebFetches to production.
3. **Catalog configuration.** The companion fetches its catalog config only from `https://aquaidp.xyz`, which returns 404 before deploy. The user shell and the MCP server therefore get `AQUA_CATALOG_CONFIG`, a local copy of the stand-in's `/.well-known/aqua-catalog.json` (the documented local override). Production does not need this.
4. **Passphrase.** The simulated user's passphrase reaches the companion through `AQUA_PASSPHRASE` in the user shell and the MCP server's env block. It is never in the agent's environment, prompt or tool arguments. The agent's `--keychain` flag stays as written; the env value wins, so the real Keychain is never read or written.
5. **source_url.** The application page is on `127.0.0.1`, so `import_local_application` correctly refused it as a non-public `source_url`. The agent then imported the saved page without a URL. A live public URL would be kept.
6. **Tarball.** Fixing `docs/AGENT.md` and `README.md` changed the packed `aqua-companion-0.2.0.tgz` (new sha256 `72e39f0d…`, version unchanged, never deployed). The run verified the published sha256 against the download (`results.json` → `tarball.match: true`).
7. **Model provider.** By design, tool results go to the agent's model provider (companion docs, "Privacy"). A6 covers every other server.

## What the agent worked out from the guidance alone

- The local companion is the agent path; nothing private goes to an AQUA server. It verified the tarball's sha256 against the published value before running anything.
- How to install and connect it, including `--workspace` after `init` and the Keychain item for `--keychain`. On the fixed guidance this took one turn (run 4); before the fix it took three (run 2).
- Files reach it only through `inbox/`, so it asked the user to save the form there.
- Approval, history confirmation, freeze, export and submission are human steps in the browser. It never tried to act around this.
- It found the stale backup, the still-unapproved Q3, the incomplete first packet and the history parse errors without being told.

## Where the guidance was unclear or wrong

Found in run 2 (before the fix) and fixed in commit `e241b1c` (`scripts/gen-agent-guidance.mjs` inputs, `/agents` page, companion `docs/AGENT.md` + `README.md`; regenerated; tarball repacked; `gen-agent-guidance --check` and `pack-site --check` clean; companion 90/90 and agent-guidance 62/62 tests pass):

1. **Local tarball under npx.** `npx --yes /abs/path/aqua-companion-0.2.0.tgz …` fails with "Permission denied", because npx treats a bare absolute `.tgz` path as a program. The guidance now gives `npx --yes --package <path>.tgz aqua-companion …` for a downloaded, verified copy.
2. **Workspace discovery.** `init --path <folder>` creates `<folder>/AQUA`. The server and the CLI find a workspace only through `--workspace`, `AQUA_WORKSPACE` or the folder they run in (or a parent). Agents added the server without `--workspace` and ran `export-backup` from elsewhere; both failed. The guidance now shows the re-add-with-`--workspace` line and puts `--workspace` on `export-backup`.
3. **`--keychain` with no Keychain item.** The install line used `--keychain`, but the guidance never told the user to create the item. It now gives `security add-generic-password -s aqua-companion -a <workspace id> -w` (workspace id from `aqua-companion status`), or says to drop `--keychain` and use `AQUA_PASSPHRASE`.
4. **History folder.** The guidance said "copy into `inbox/`", but `import_history` takes a folder inside `inbox/`. It now says `inbox/history/` and `import_history { folder: "history" }`.
5. **Wording.** "Clients must publishable/anon key only" now reads "Clients must use the publishable/anon key only; they refuse any other role…".

Not guidance, so not fixed here. These are reported for the companion owner:

- **History parser (`aqua-companion/src/history-parse.mjs`).**
  - In a plain `.docx` without heading styles, the second question ("How will you use the grant funds?") and its answer are merged into the first answer, and the program name is taken from the filename rather than the first line.
  - In a `.md` with a `Submitted:` line followed by `## question` and a paragraph, the answer was read as the question, and the real question shows as unanswered.
  - The agent caught both, and the vault's history screen would show the wrong text. A careless user could still confirm a mis-parsed answer as "submitted".
- **`match_canonical_questions`** returned no catalog matches, because no canonical questions were cached; the agent did not call `refresh_catalog` first. The tool's note says to, so this is minor.

## Repeat on production

After GB3 (merge + deploy), from a checkout of the merged branch:

```sh
node docs/evidence/m09b/at23/run-at23.mjs --site https://aquaidp.xyz --evidence <new folder>
```

With `--site`, no stand-in is started and no catalog-config override is set. The agent gets no "pre-release copy" note. The application page is still served locally, so `source_url` is still refused (deviation 5). The AQUA server log cannot be captured, so A6 covers the application page, every companion `fetch` and the agent's WebFetch URLs. `--mode scripted` runs the documented JSON-RPC fallback without a model.
