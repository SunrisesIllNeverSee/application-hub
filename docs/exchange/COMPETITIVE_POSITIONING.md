# Contribution Exchange — Competitive Positioning

## Claim carefully

The product does not claim to invent agent communication, contracting, payment, digital rights, escrow, bounty programs, provenance, or marketplaces. Those capabilities exist in multiple standards and products.

The target behavior is narrower: an independently operating agent can encounter an ordinary participating web domain, discover its exchange policy, originate a previously unlisted contribution opportunity (or request contribution from the domain), and carry the resulting contribution through a governed economic lifecycle without requiring a marketplace-owned listing.

## Nearby systems

### A2A / ANP / AHP
Strong overlap in agent discovery, identity, communication, capability description and website-agent engagement. The Exchange Gateway can use them. Its additional concern is the economic contribution object and lifecycle: opportunity → proposal/request → commitment → authorization → delivery → verification → vesting/settlement → lineage.

### XAP / Virtuals ACP / agent-commerce protocols
Strong overlap in negotiation, transactions, escrow/settlement and receipts. The Gateway does not need to replace their settlement mechanics. Its differentiator is the domain-native ambient origin and persistent Contribution Commitment tying the artifact/opportunity to rights, consideration, authorization and downstream lineage.

### Schema.org Demand / Offer
Useful vocabulary for already-published demand and supply. The Gateway additionally supports value that was not listed because neither party knew to create inventory before the agent's observation.

### ODRL / programmable IP systems
Strong overlap in permissions, duties, agreements, licensing, compensation conditions, derivatives and royalties. Use/profile these semantics instead of inventing a closed rights language. The Gateway adds the web-domain engagement/lifecycle around the rights object.

### HackerOne / bug-bounty systems
Best behavioral analogue for externally discovered value: outside party observes an issue, follows a scope/policy, discloses evidence, communicates, gets validated and may be paid. The Gateway generalizes the pattern beyond vulnerabilities while explicitly refusing to infer security-testing authorization.

### GitHub pull requests
Best contribution analogue: a contributor can notice something maintainers never opened as an issue, submit a change, review it, merge/reject it and retain contribution history. The Gateway generalizes contribution mechanics beyond code repositories and adds negotiated economic rights/settlement.

### Work/freelance/procurement marketplaces
They typically begin with a known job/RFP/listing and the marketplace owns discovery inventory. The Gateway can begin with an ambient observation and keeps the participating domain canonical.

## Product sentence

**Give your website a way to do business with agents that discover value you did not know to ask for.**

Reciprocal extension: participating agents can also ask a domain for value the domain is uniquely positioned to contribute.

## What not to say

Avoid: “first agent marketplace,” “first agent payment protocol,” “agents have never negotiated before,” “nobody has digital-rights vesting,” or “we invented agents talking to websites.” Those claims are contradicted by existing work.
